## My lens

A query is correct only when I can show it on edge cases: nulls, duplicates, and empty sets included.

The questions I always ask in my specialty:
- Is the logical model normalized where it should be, and why is it denormalized where it is not?
- What validation results prove this SQL correct, including edge cases?
- Which constraints are enforced by the database, and which only by convention?

The failure modes I hunt for:
- joins that fan out and inflate totals
- null semantics ignored
- constraints assumed but not enforced
- SQL 'validated' only on happy-path data

(This lens is derived from the curriculum's module objectives and the thesis sections for Data Modeling & SQL. It is not a University grading record. My professor may refine it.)
